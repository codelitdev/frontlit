# Developer documentation platforms versus the FrontLit docs baseline

Research date: 2026-10-10. Primary sources were fetched that day unless a published date is noted. The FrontLit baseline in the assignment (signed off 2026-10-03, no production) is the comparison target and was not re-researched. June 2026 write-ups that say Mintlify dropped Pro, or that put AI on the free tier, are stale relative to the pricing page captured on 2026-10-10.

## For each of Mintlify, GitBook, ReadMe, Fern, and Archbee, what is the canonical authoring model in October 2026, and what is plan-gated?

### Takeaway
All five are hybrids, but the source of truth differs. Mintlify, Fern, and ReadMe are docs-as-code (MDX or Markdown plus an API spec) with a web editor on top. GitBook and Archbee are block WYSIWYG editors that can sync Markdown to Git. OpenAPI-generated reference is part of the product on every platform and is not an add-on. Plan gates hit collaboration, AI, previews, and branding more often than the basic editor.

### Cited Findings
- Mintlify’s public docs are MDX: the docs index describes MDX templates, an MDX editor extension, and a help article titled “Publish button disabled because of invalid MDX,” which blocks publish until invalid MDX is fixed. OpenAPI is a first-class source: there is a guide for migrating hand-written MDX API pages to OpenAPI-generated navigation, and endpoint frontmatter (`openapi`, `api`, `asyncapi`) is validated at deploy. A web editor edits the connected repository, including a branch dropdown. — [Mintlify docs index](https://www.mintlify.com/docs/llms.txt); [invalid MDX help](https://www.mintlify.com/docs/help-center/publish-button-disabled-invalid-mdx.md); [MDX-to-OpenAPI migration](https://www.mintlify.com/docs/guides/migrating-from-mdx.md); [endpoint frontmatter help](https://www.mintlify.com/docs/help-center/endpoint-frontmatter-must-be-a-single-string.md); [editor branch list](https://www.mintlify.com/docs/help-center/branch-missing-from-editor-branch-list.md)
- Mintlify plan gates on the pricing page captured 2026-10-10: Starter ($0, 5 editor seats) includes the web editor, Git sync, API playground, search, MCP server, custom domain, built-in components, custom components, and custom CSS/JS. Pro adds unlimited editors, the writing agent (unlimited, no credits), Assistant, automations, AI translations, preview deployments, user feedback, webhooks, developer API, and platform analytics. Enterprise adds multi-repo, integrations, search filters, white labeling, SSO/SCIM/RBAC, OAuth/JWT reader auth, personalization, and self-hosting/EU hosting as available. Assistant and automations are not on Starter. — [Mintlify pricing](https://www.mintlify.com/pricing)
- GitBook’s canonical editor is a block-based WYSIWYG with Markdown support, on every plan including Free. Git Sync (GitHub or GitLab, two-way) is also on every plan, including Free. Import sources listed on the pricing page include Markdown, Google Docs, Confluence, Notion, and MS Word. API playground blocks are on every plan. Custom domain, real-time collaboration, reusable content, and review-and-approve are Essential and above, not Free. — [GitBook pricing](https://www.gitbook.com/pricing); [Git Sync overview](https://gitbook.com/docs/docs-as-code/git-sync)
- ReadMe’s canonical model is a developer hub: Markdown guides plus an OpenAPI (or Swagger) API reference with a Try It console, edited in a web editor and/or a Git repo. Quickstart step 2 is “upload your OpenAPI specification.” Bi-directional sync stores guides as Markdown with required `title` and `summary` frontmatter and `_order.yaml` navigation. Custom MDX components are listed on the Pro plan card, not Starter. Starter still includes the Markdown editor, API reference, customizable themes, custom domain, and bi-directional sync. — [ReadMe pricing](https://readme.com/pricing); [Quickstart](https://docs.readme.com/main/docs/quickstart); [Bi-directional sync](https://docs.readme.com/main/docs/bi-directional-sync); [Documentation structure](https://docs.readme.com/main/docs/documentation-structure)
- ReadMe docs updated 2026-09-25 say new projects should use Git Connection plus `@readme/cli`. The older `rdme` upload path is one-way: editor changes do not flow back to files, and that path does not provide branches or reviews. OpenAPI 3.0 or 3.1 is the supported spec. Bi-directional sync, the API reference, and Try It are described as included on Starter, Pro, and Enterprise. — [Sync docs with OpenAPI](https://docs.readme.com/main/docs/sync-docs-with-openapi)
- Fern Docs is docs-as-code: MDX guides in Git, configuration in `docs.yml`, generated with the Fern CLI (`fern generate --docs`, local preview `fern docs dev`). The same spec generates the API reference. The Docs pricing tab (captured 2026-10-10) says Free includes a web editor, Markdown guides, API explorer, changelogs, and docs-as-code. Specs listed: OpenAPI, OpenAPI Overlays, OpenAPI Arazzo, AsyncAPI, gRPC, GraphQL, OpenRPC, plus REST, webhooks, WebSockets, SSE, and Protobuf. Fern’s own product page says “MDX for prose” and “write content in MDX, version it in Git.” — [Fern pricing](https://buildwithfern.com/pricing); [preview changes](https://buildwithfern.com/learn/docs/preview-publish/preview-changes); [Fern docs product page](https://buildwithfern.com/docs.md)
- Fern Free versus Enterprise, from that same pricing page: Free is 10 members, 1 site, 1,000 pages, 250 AI credits/month, 2,000 page generations/month, custom domain and subpath, version and product switching, Ask Fern, Fern Agent, and an MCP server. Enterprise adds SSO, SCIM, advanced RBAC, multiple repos and docs instances, custom CSS/JavaScript/React components, custom layouts and design-system integration, self-hosting, and removal of Fern branding (the last items are under Enterprise or marked Custom). Checkmarks for localization, AI translations, and PDF export did not survive extraction, so their plan column is not confirmed here. — [Fern pricing](https://buildwithfern.com/pricing)
- Archbee’s canonical editor is a block WYSIWYG with Markdown shortcuts. Help docs group blocks under Basic, Media, Developer, Embed, and Content Reuse, and document dynamic links that survive moves. GitHub Markdown is an alternative authoring path, not the only one. OpenAPI/Swagger or Postman collections import into a three-column reference. Confluence is documented as an AI external source (credentials plus a space key), not as the publishing source of truth. — [Create a docs website](https://www.archbee.com/docs/create-a-docs-website); [Editor index](https://www.archbee.com/docs/editor); [Learn the basics](https://www.archbee.com/docs/learn-the-basics); [Import Confluence pages](https://www.archbee.com/docs/import-confluence-pages)
- Archbee plan cards captured 2026-10-10: Growing includes public/private portals, custom domain and branding, custom JavaScript, password protection, GitHub integration, and API documentation. Scaling adds complete branding control, a review system, reusable content and variables, and versioning and localization. Document revision history is documented on Growing, Scaling, and Enterprise, which is separate from product versioning. — [Archbee pricing](https://www.archbee.com/pricing); [Documents index](https://www.archbee.com/docs/documents)

### Inferences
- Against the FrontLit baseline (TipTap JSON or one GitHub repo of Markdown, no MDX/JSX, no OpenAPI reference), every heavyweight treats rich components and generated API reference as normal authoring, not an edge. FrontLit’s “unknown frontmatter retained, MDX rejected” rule is the opposite of Mintlify, Fern, and ReadMe Pro, which require valid MDX or spec-shaped frontmatter.
- The closest authoring match to FrontLit’s Git mode is Fern or Mintlify (repo is canonical, web editor is a client). The closest match to FrontLit’s visual editor is GitBook or Archbee (blocks in a hosted editor, Git optional). None of the five force a single choice of “editor XOR Git” the way FrontLit does; they run both at once.
- Notion and Confluence appear as importers (GitBook) or AI context (Archbee), not as the live publishing source. That matches FrontLit’s non-goal of Notion/Confluence as a source, but GitBook will still ingest those files.

### Gaps
- Mintlify’s docs index no longer lists a `docs/organize/` section (195-line `llms.txt` on 2026-10-10 had zero matches). A dedicated versions or navigation guide was not opened. Versions are only confirmed indirectly: a help article says search can fail because of `hidden: true` on a version in `docs.json`. — [site search help](https://www.mintlify.com/docs/help-center/site-search-returns-no-results.md)
- Fern’s pricing page has a Docs/SDKs toggle and a Postman Customer view. This pass captured the Docs tab only. A self-serve “Team” plan around $150/month appears in October 2026 third-party trackers and was not on the rendered official Docs tab. Do not treat $150 as a Fern list price.
- Archbee’s feature matrix on the pricing page did not render row labels or checkmarks in the fetch, so gates that are not in the plan cards or help center are unconfirmed.

## Which of navigation, multi-product docs, versioning, localization, redirects, custom domains, theming, components, and OpenAPI or SDK generation are table stakes?

### Takeaway
Table stakes across this set, usually on the free or entry plan, are a custom domain, nested navigation, themed docs, callout/tab-style components, and an OpenAPI reference with a try-it console. Product versioning and localization exist on all five in some form, but Archbee holds both for the Scaling plan, and GitBook holds multi-product sections and custom subdirectories for Ultimate. SDK generation is not table stakes. Only Fern sells it as a core product.

ReadMe Starter includes customizable themes; the Pro card adds CSS/HTML; Enterprise adds removal of ReadMe branding. ### Inferences
- Relative to FrontLit (one `/docs` area, flat sections, nested URLs allowed but nested section navigation not, no version switcher, no locales, no redirects, no configurable prefix, no second collection, no OpenAPI), the heavyweights’ table stakes are exactly FrontLit’s explicit non-goals plus nested navigation and a docs-specific theme.
- “One docs site on the marketing domain” is not how these products are shaped. They expect a dedicated docs host (`docs.company.com` or a subdirectory on higher tiers). Fern and GitBook Ultimate are the ones that document a subpath on the main site. FrontLit’s fixed `/docs` on the team marketing site, sharing header and footer, is narrower than all of them.
- SDK generation and multi-product hubs are differentiators, not table stakes. A buyer comparing FrontLit to this set will notice the missing API reference before they notice missing SDKs.

### Gaps
- Mintlify navigation depth, version URL shape, and redirect configuration were not opened as current guide pages. The `docs/organize/` path 404ed.
- Fern localization’s plan gate did not render. Whether it is Free or Enterprise is unverified.
- Archbee redirect support, beyond customers terminating redirects at Cloudflare, was not found in official docs opened here.
- ReadMe’s plan columns for 404 redirects, themes versus custom JS, and AI translations were flattened in the fetch. Only the plan cards are safe for gating claims.

## How complete are GitHub or GitLab sync, PR previews, branch previews, bi-directional editing, and review-before-publish?

### Takeaway
All five sync with GitHub. GitLab is first-class on GitBook and ReadMe, and Mintlify’s October 2026 changelog shows GitLab multi-repo previews working. “Bi-directional” does not mean the same review gate. ReadMe and GitBook can write straight to the live branch. Mintlify and Fern keep production on the deploy branch and preview PRs separately. Archbee treats GitHub as source of truth and turns editor edits into pull requests a human merges.

### Cited Findings
- Mintlify: Git sync is on Starter, Pro, and Enterprise. Preview deployments are not on Starter; they are on Pro and Enterprise. Docs say each pull request gets a unique preview URL. An October 2026 changelog says GitHub previews are pinned to the triggering commit, URLs stay stable across rebuilds, retargeting a PR onto the deploy branch creates a preview, and GitLab multi-repo preview deployments work. The Assistant indexes published docs only, not draft branches or preview deployments. A public Preview Deployment API exists (changelog, 2026-04-24) for workflows that are not standard branch previews. The web editor has a branch dropdown and a live preview that does not create a deployment. Multi-repo is Enterprise-only. Instant rollbacks are marked not included on Starter and Pro, so Enterprise-only on the captured matrix. — [Mintlify pricing](https://www.mintlify.com/pricing); [Preview deployments](https://www.mintlify.com/docs/deploy/preview-deployments.md); [Mintlify changelog](https://www.mintlify.com/docs/changelog); [Assistant](https://www.mintlify.com/docs/assistant); [editor branch help](https://www.mintlify.com/docs/help-center/branch-missing-from-editor-branch-list.md)
- GitBook: Git Sync is bi-directional with GitHub or GitLab on every plan, including Free. Administrators and creators configure it. As of the 2026-09-03 changelog, an entire site can sync to one repo via `gitbook-docs.yaml`; previously sync was per space. Enterprise adds a fixed outbound IP range for allowlisting. Change requests are GitBook’s branch-and-merge review on every plan; review-and-approve and merge rules start at Essential. Preview deployments of content edits are on every plan. Git Sync does not mirror pull requests: a GitHub PR does not create a GitBook change request, and a change request does not create a GitHub or GitLab PR. Commits GitBook pushes use messages like `GITBOOK-14: …`. — [Git Sync](https://gitbook.com/docs/docs-as-code/git-sync); [GitBook changelog 2026-09-03](https://gitbook.com/docs/changelog); [GitBook pricing](https://www.gitbook.com/pricing); [PRs are not synced](https://gitbook.com/docs/help-center/integrations/existing-integrations/git-sync/does-git-sync-also-sync-pull-requests); [commit messages](https://gitbook.com/docs/docs-as-code/git-sync/commits)
- ReadMe: bi-directional sync with GitHub, GitLab, and Bitbucket is documented with a plan marker of Starter. The target repository must be empty before connect. Editor saves become commits on the synced branch, and Git commits flow back. ReadMe pushes directly to those branches. Branch protection that requires a PR, review, or status check rejects the push unless the ReadMe app is on the bypass list; the connection can still look Connected. Feature branches in ReadMe map 1:1 to Git branches, and merging a feature branch into the main version branch is what goes live. Branching and reviews are on the Pro card, not the Starter card. Only the main version syncs on first enable; other versions sync after that. Changelog posts gained Git sync on 2026-09-14, rolled out gradually. GitHub Enterprise Server sync is Enterprise-only. — [Bi-directional sync](https://docs.readme.com/main/docs/bi-directional-sync); [Sync with OpenAPI](https://docs.readme.com/main/docs/sync-docs-with-openapi); [ReadMe pricing](https://readme.com/pricing); [Changelog 2026-09-14](https://docs.readme.com/main/changelog/changelogs-in-git)
- Fern: publishing is CLI or CI (`fern generate --docs`). Hosted PR previews are documented as a GitHub Actions workflow the customer installs: `fern generate --docs --preview --id <branch>` posts a stable preview URL and links to changed MDX pages. That is not a vendor-managed GitHub App that previews every PR with no workflow. Local preview is `fern docs dev`, which the 2026-08-06 changelog says does not preview versions pinned to a git ref. Preview links can be deleted with `fern docs preview delete`. Free includes preview links on the pricing matrix (the row is listed; the check column was messy, and the product docs present previews as part of the workflow rather than an Enterprise add-on). Multiple repo sources are marked Custom, matching the Enterprise “multiple repos” bullet. — [Preview changes](https://buildwithfern.com/learn/docs/preview-publish/preview-changes); [Fern changelog 2026-08-06](https://buildwithfern.com/learn/docs/changelog/2026/8/6); [Fern pricing](https://buildwithfern.com/pricing)
- Archbee: the help page “GitHub 2-way sync” (search metadata 2026-06-18) says changes in GitHub and in Archbee both propagate, but GitHub stays the source of truth. An editor publishes by “Push to Github Pull Request”; merging the PR updates Archbee. Sync watches a selected branch; opening pull requests into that branch triggers sync, with a manual “Sync with repo” fallback. A May 2024 product post (possibly stale on details, useful as the ship date) announced this two-way PR loop; an October 2023 post had said one-way only, which is superseded. A separate “Branches & Reviews” system is beta as of a page updated 2026-06-12: Git-style branches inside Archbee, including for GitHub-connected spaces, but only for newly created spaces that opt in, and existing spaces cannot be switched during beta. The Scaling plan’s “review system” is a separate priced feature on the pricing card. GitLab is named on Archbee’s developer-docs marketing page; the official sync article opened here is GitHub-only. — [GitHub 2-way sync](https://www.archbee.com/docs/github-2-way-sync); [GitHub setup](https://www.archbee.com/docs/github); [Branches and reviews](https://www.archbee.com/docs/branches-and-reviews); [May 2024 update](https://www.archbee.com/blog/archbee-may-2024-product-updates); [2023 one-way post, superseded](https://www.archbee.com/blog/our-github-and-jira-integrations-are-here); [Developer docs marketing](https://www.archbee.com/solutions/developer-api-documentation); [Archbee pricing](https://www.archbee.com/pricing)

### Inferences
- FrontLit’s rule (one publishing branch is the only live source; feature branches and open PRs do not go live; editor proposals are PRs or direct commits; conflicts and checks are explicit) is stricter than ReadMe and looser than “no preview at all.” Mintlify Pro and Fern’s preview workflow are the products that already separate preview from production the way FrontLit separates draft from publication. ReadMe’s default, if branch protection is off, is save-publishes.
- GitBook’s change request is a real review gate inside GitBook, but it is not a GitHub PR. A team that reviews only in GitHub will not see GitBook edits until they land as commits. That is a weaker GitHub review story than Archbee’s “editor opens a PR” or FrontLit’s “drafts proposed as PRs.”
- None of the five require whole-candidate validation that leaves the last good publication untouched, which is FrontLit’s publish rule. The nearest equivalents are Mintlify refusing to publish invalid MDX, Fern CI checks the customer wires in, and ReadMe’s `@readme/cli` lint before push. Those are file or build checks, not a documented immutable publication history with automatic rollback to last-good on a failed full-tree validate. Mintlify Enterprise has instant rollbacks of a previous successful build, which is adjacent but plan-gated.

### Gaps
- Whether Mintlify’s web editor commits to the deploy branch directly or only through a PR was not stated on the pages opened. The branch dropdown shows the editor can target a branch. The publish button exists and is disabled on invalid MDX.
- Fern preview links are documented as a sample workflow, not as a default that turns on when you install an app. How often customers actually enable it is unknown.
- Archbee GitLab parity with the GitHub PR loop was not confirmed in a help article.
- ReadMe does not document a hosted, shareable preview URL distinct from a branch the way Mintlify does. “Shareable branches” is a row on the pricing table without a confirmed plan column.

## What are the named AI authoring, AI search or chat, and feedback-to-draft features, and are citations required?

### Takeaway
Reader chat that cites documentation pages is shipped and documented for all five. It is not on the free tier everywhere: Mintlify and full GitBook chat are paid, ReadMe’s full Ask AI is a $150/month add-on, and Archbee Ask AI is an add-on. Authoring agents are separate products (Mintlify writing agent, GitBook Agent, ReadMe Agent, Fern Agent, Archbee AI Write). The feedback loop that turns support traffic into a draft exists most clearly at GitBook (content gaps plus connections) and as a partial loop at Mintlify (automations and support integrations). None of them are the support inbox.

### Cited Findings
- Mintlify Assistant (Pro and Enterprise, not Starter) answers from published docs, cites sources with links, can read images on pages it can access, uses the current page as context, and returns OpenAPI method and schema detail. If it cannot answer it says so, and that miss costs 0 credits; a successful answer costs 25 credits. It does not index draft branches, preview deployments, or hidden pages unless `seo.indexing` is `"all"`. A deflection email can be set when it cannot answer. ## What do these products deliberately not do, so a comparison with a front office stays honest?

### Takeaway
These are documentation hosts with optional chat, Git, and API reference. They connect to support tools. They do not replace a shared inbox, outbound email, or a marketing-site builder. GitBook and Archbee stretch toward help centers and knowledge portals. ReadMe stretches toward an API consumer dashboard. None of them is a multi-product SaaS front office.

### Cited Findings
- GitBook’s Assistant system, via the connections doc, indexes other companies’ support tools (Intercom, Zendesk, Freshdesk, Front, HubSpot, Zoho Desk, Pylon). It does not present GitBook as the ticket system. Authenticated access, site sections, and adaptive content are docs-site features on Ultimate, marketed for “product hubs, developer portals, help centers,” meaning a docs information architecture, not an agent inbox. The pricing FAQ list includes “Does GitBook support self-hosting?” as a question; the captured answer body was not expanded, so self-host is not asserted here. SAML SSO is Enterprise-only. — [Connections](https://gitbook.com/docs/ai-for-your-readers/connections); [GitBook pricing](https://www.gitbook.com/pricing)
- ReadMe integrates with Intercom, Zendesk, Slack, and Segment rather than listing an inbox or email product. It does ship developer-hub pieces FrontLit would call neighboring products: changelog, recipes, discussion forums, a landing page (Pro card), and a developer dashboard of API request history (24 hours on every plan, extended history $100/month). Forums and the landing page are not a marketing site builder. Enterprise can remove ReadMe branding and combine projects. There is no published website-builder or outbound-email product on the pricing page. — [ReadMe pricing](https://readme.com/pricing)

### Inferences
- FrontLit’s positioning (one published document is the website page, the chatbot citation, and the ticket-reply source, inside a front office that also has blog, changelog, inbox, and email) is not a feature these five lack by accident on a pricing tier.
